### TP 1


🐳 Installer Docker sur Ubuntu
1️⃣ Mettre à jour le système
```
sudo apt update
sudo apt upgrade -y
```
✅ INSTALLATION DOCKER VIA SNAP (RECOMMANDÉ ICI)
2️⃣ Installer Docker
```
sudo snap install docker
```

⏳ Attends la fin de l’installation.

3️⃣ Vérifier que Docker fonctionne
```
docker --version
```

Puis :
```
sudo docker run hello-world
```

🎉 Si tu vois le message de succès, Docker est opérationnel.

3️⃣ (Optionnel) Docker sans sudo
```
sudo addgroup --system docker
sudo adduser $USER docker
newgrp docker
```

Une fois Docker fonctionnel :
```
docker run -d -p 8080:80 --name web nginx
```

Puis :
```
http://localhost:8080
```

✅ 1. Vérifier le fonctionnement de Nginx
🌐 Navigateur

Ouvre :
```
http://localhost:8080
```

👉 Tu dois voir “Welcome to nginx!”

💻 Ligne de commande (optionnel)
```
curl http://localhost:8080
```
✅ 2. Explorer le conteneur
📋 Lister les conteneurs en cours
```
docker ps
```

👉 Tu dois voir un conteneur nommé web avec le port 0.0.0.0:8080->80/tcp

🔍 Infos détaillées du conteneur
```
docker inspect web
```

À repérer (pas besoin de tout comprendre) :

- IP du conteneur
- Ports exposés
- Image utilisée (nginx)

📜 Logs en temps réel
```
docker logs -f web
```

Recharge la page dans ton navigateur → tu verras les requêtes s’afficher.
👉 Ctrl + C pour quitter.

✅ 3. Interagir avec le conteneur
🖥️ Ouvrir un shell interactif
```
docker exec -it web bash
```

👉 Tu es maintenant dans le conteneur.

✏️ Modifier la page web

Installe un éditeur simple :
```
apt update
apt install -y nano
```

Puis :
```
nano /usr/share/nginx/html/index.html
```

Remplace le contenu par :
```
<h1>Mon premier conteneur !</h1>
```

➡️ Sauvegarder : Ctrl + O, Entrée
➡️ Quitter : Ctrl + X

🌐 Vérifier

Recharge :
```
http://localhost:8080

```
🎉 Tu dois voir Mon premier conteneur !

✅ 4. Nettoyer
⏹️ Arrêter le conteneur
```
docker stop web
```
🗑️ Supprimer le conteneur
```
docker rm web
```

Vérification :
```
docker ps
```

👉 Il ne doit plus apparaître.

🧠 Questions de réflexion (réponses prêtes à rendre)
❓ Si on recrée le conteneur après suppression ?

👉 La modification disparaît
Un conteneur repart toujours depuis l’image d’origine.

❓ Comment persister la modification ?

Avec un volume Docker

Ou avec une image personnalisée (Dockerfile)

Exemple volume :

docker run -d -p 8080:80 \
-v $(pwd)/site:/usr/share/nginx/html \
--name web nginx

❓ Différence entre arrêter et supprimer ?

docker stop → le conteneur est arrêté mais existe toujours

docker rm → le conteneur est supprimé définitivement


### 🧱 TP 2 – Construction d’image Docker personnalisée
🎯 Objectif

Créer ta propre image Docker au lieu de modifier un conteneur à la main.

1️⃣ Préparer le projet
📁 Créer le dossier du projet
```
mkdir tp2-docker
cd tp2-docker
```

📄 Créer le fichier HTML
```
nano index.html
```

👉 Contenu version 1.0 :
```
<!DOCTYPE html>
<html>
<head>
    <title>Mon site Docker</title>
</head>
<body>
    <h1>Mon site - Version 1.0</h1>
</body>
</html>
```

➡️ Sauvegarder : Ctrl + O → Entrée
➡️ Quitter : Ctrl + X


2️⃣ Écrire le Dockerfile
📄 Créer le Dockerfile

⚠️ Sans extension
```
nano Dockerfile
```
📦 Contenu du Dockerfile
```
FROM nginx:alpine

COPY index.html /usr/share/nginx/html/index.html

EXPOSE 80
```
🧠 Explication

FROM nginx:alpine → image légère

COPY → ajoute ton fichier HTML dans Nginx

EXPOSE 80 → documente le port utilisé


3️⃣ Construire l’image
🔨 Build de l’image (version 1)
```
sudo docker build -t mon-site:v1 .
```

👉 Tu verras :

téléchargement de l’image de base

étapes (layers) FROM, COPY, EXPOSE

🔍 Vérifier les images
```
sudo docker images
```

4️⃣ Tester l’image
▶️ Lancer un conteneur avec v1
```
sudo docker run -d -p 8081:80 --name site-v1 mon-site:v1
```
🌐 Vérifier dans le navigateur
```
http://localhost:8081
```

👉 Tu dois voir : Mon site – Version 1.0

5️⃣ Itérer (version 2)
✏️ Modifier le HTML
```
nano index.html
```

Remplace par :
```
<h1>Mon site - Version 2.0</h1>
```
🔨 Rebuild avec un nouveau tag
```
sudo docker build -t mon-site:v2 .
```
▶️ Lancer la version 2
```
sudo docker run -d -p 8082:80 --name site-v2 mon-site:v2
```
🌐 Vérification

- Version 1 → http://localhost:8081
- Version 2 → http://localhost:8082

👉 🎉 Les deux versions tournent en même temps

6️⃣ Nettoyer
⏹️ Arrêter les conteneurs
```
sudo docker stop site-v1 site-v2
```
🗑️ Supprimer les conteneurs
```
sudo docker rm site-v1 site-v2
```

🧠 Questions de réflexion (réponses)
❓ Pourquoi utiliser alpine ?

Image beaucoup plus légère

Démarrage plus rapide

Moins de surface d’attaque sécurité

❓ Que se passe-t-il si on rebuild sans changer le tag ?

L’ancienne image est écrasée

Les conteneurs existants continuent avec l’ancienne version

Les nouveaux conteneurs utilisent la nouvelle image

❓ Comment voir toutes les images ?
```
docker images
```


### 🐳 TP 3 – Docker Compose : Stack WordPress
1️⃣ Créer le projet
```
mkdir wordpress-compose
cd wordpress-compose
```
2️⃣ Créer le fichier docker-compose.yml

Crée un fichier docker-compose.yml :
```
nano docker-compose.yml
```

Copie-colle ce contenu :
```
version: '3.8'

services:
  wordpress:
    image: wordpress:latest
    ports:
      - "8080:80"
    environment:
      WORDPRESS_DB_HOST: db:3306
      WORDPRESS_DB_USER: wp_user
      WORDPRESS_DB_PASSWORD: wp_pass
      WORDPRESS_DB_NAME: wordpress_db
    volumes:
      - wordpress_data:/var/www/html
    depends_on:
      - db

  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: root_pass
      MYSQL_DATABASE: wordpress_db
      MYSQL_USER: wp_user
      MYSQL_PASSWORD: wp_pass
    volumes:
      - db_data:/var/lib/mysql

  phpmyadmin:
    image: phpmyadmin:latest
    ports:
      - "8081:80"
    environment:
      PMA_HOST: db
      PMA_USER: root
      PMA_PASSWORD: root_pass
    depends_on:
      - db

volumes:
  wordpress_data:
  db_data:
```
LALALALA
3️⃣ Lancer la stack
```
docker-compose up -d
```
Vérifier que tout tourne
```
docker-compose ps
```

Tu dois voir 3 conteneurs : wordpress, db, phpmyadmin.

Voir les logs WordPress
docker-compose logs -f wordpress

4️⃣ Tester
WordPress

Ouvre dans le navigateur : http://localhost:8080

Termine l’installation (choix de langue, compte admin, etc.)

Crée un article test

phpMyAdmin

Ouvre : http://localhost:8081

Connecte-toi avec :

User : root

Password : root_pass

Vérifie que la base wordpress_db existe

5️⃣ Vérifier la persistance

Arrêter et supprimer les conteneurs sans les volumes :

docker-compose down


Relancer :

docker-compose up -d


✅ Ton article WordPress doit être toujours là, car le volume wordpress_data persiste.

6️⃣ Bonus : Ajouter Nginx comme reverse proxy

Exemple d’ajout dans docker-compose.yml :

  nginx:
    image: nginx:latest
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - wordpress


Exemple minimal de nginx.conf :

server {
    listen 80;
    server_name localhost;

    location / {
        proxy_pass http://wordpress:80;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

7️⃣ Questions de réflexion
Question	Réponse courte
Pourquoi utilise-t-on depends_on ?	Pour que WordPress et phpMyAdmin attendent que la base de données MySQL soit prête avant de démarrer.
Différence entre volume nommé et bind mount	Volume nommé : géré par Docker, persiste même si conteneur supprimé.
Bind mount : répertoire de l’hôte directement monté, utile pour le développement.
Comment les services communiquent-ils ?	Par le nom du service dans le réseau Docker Compose (DNS interne) : db, wordpress, etc.
